## 1. 结论摘要

v0.6 已经把城市森林遥感任务放在源定义、背景、三项不足、科学问题、技术路线和创新边界的共同起点。三项研究的对象与验证责任也已明显区分：第一项检验工作流形成／运行／恢复，第二项检验知识与证据机制，第三项检验固定真实任务中的系统结果与过程。Route B 的只读离线边界、`manual 301` 的样本角色、RSS 的分支边界，以及“城市级”不单独构成创新，均没有被不当晋级。

需要优先修正的不是总体故事，而是两处正文与当前写作规划／已接受决策之间的错位。处理后再做引文准入，能显著降低导师阅读时把论文误解为“通用 Agent 三模块拼接”或把 Route B 误读为尚未决定路线的风险。

## 2. 需要处理的发现（最多五项）

### P1-01：研究动态没有落实“先城市森林、后智能体”的既定小节结构

- **证据**：原子论述图将 `2.1` 明确设为“城市森林遥感任务与方法基础”，其职责是先交代问题域的数据、方法、产品与专家组织的研究流程；正文 `2.1–2.5` 仍从“大语言模型智能体与科学智能体研究”开始，且没有与该职责对应的城市森林方法基础小节。
- **影响**：第 1 节与第 2.5 节虽已从城市森林问题出发，但研究动态的证据链仍先由通用 Agent 文献建立。导师可能因而认为城市森林只是案例场景，而非问题牵引。
- **最小修复**：在第 2 节新增／恢复“2.1 城市森林遥感任务与方法基础”，只写任务类型、数据／尺度／验证／解释要求及专家流程边界；将既有 `2.1–2.4` 顺延为 `2.2–2.5`，现有不足节为 `2.6`。不扩展成城市森林遥感全综述，不用“数据很多”作为贡献论据，保留所有 `[REF-MISSING]` 直到引文准入完成。

### P1-02：Route B 已接受状态在正文中仍有“推荐／待确认”的旧表述

- **证据**：`DEC-2026-0902-ch3-routeb-first-evaluation-order.md`、`THESIS_STATE.md` 和 O1 v0.6 brief 均确认 Route B 为首个评测任务／首个最小评测实现。正文 `3.5` 仍写“首轮仍推荐”，`4.4` 又写“该路线在研究者确认前不写成已冻结方法”。
- **影响**：这会把已经关闭的实施顺序门禁重新打开，削弱“Route B 是首个最小实现、但不是第三章全部路线”的清楚边界。
- **最小修复**：统一为“首轮采用 Route B 只读离线治理链；它已由研究者确认为首个评测任务／首个最小评测实现”。随后保留三个关键限定：不等于第三章全部路线；不表示 GEE 专业流程迁移为本地算法；不支持系统效果已验证。此处不应把“首个实现顺序已接受”误写成“第三章完整方法已冻结”。

### P2-01：第一章增量机制的名称有轻微漂移

- **证据**：章级源定义使用“可调整的分层规划、随执行更新的过程图、错误调节、受控停止和基于检查点的局部恢复”；正文 `4.2`、`6.1–6.2` 则改用“动态规划、过程图”。
- **风险**：“动态规划”在方法学语境中有既定含义，可能被读成不同于“可调整的分层规划”的算法主张；“过程图”也弱化了其随执行更新的属性。
- **最小修复**：在首次出现处使用源定义全称，后文仅在已定义时使用受控简称；优先保留“可调整的分层规划”和“随执行更新的过程图”。这属于术语收口，不改变第一章机制或效果状态。

### P2-02：第二章的“科学意图”尚未在正文中给出可操作含义

- **证据**：它在源定义、路线矩阵和正文中作为评价维度出现（与产品正确性、严重科学错误、不必要干预并列），但没有首次定义其对应的可观察判断对象。
- **风险**：这是必要的跨章评价概念，但若不界定，容易成为自创术语，也会与第三章的“科学一致性”发生语义重叠。
- **最小修复**：首次使用时将其约束为“任务所要求的观测、分析、验证与结论边界是否被满足”，并说明其与产品正确性、系统过程评价分别承担什么责任。定义之后，第二章使用“科学意图满足”，第三章保持“任务组织、依赖与过程的系统评价”，不将两者合并。

### P3-01：第三章段落信息密度偏高，但边界处理本身正确

- **证据**：`3.5` 在一个研究内容单元中同时承载 Route B 案例、离线限制、核心栖息地、RSS、错误传播、三类系统比较、领域校准、107／63 条资产记录和预期成果。
- **影响**：概念均有必要，却可能使导师第一次阅读时先看见实施细节，后看见“真实任务环境—最小评测接口—系统边界”的主句。
- **最小修复**：不删边界；只把 Route B 的具体误晋级情形与 RSS 细分状态留给 `4.4` 或技术路线图，在 `3.5` 保留“首轮冻结 2–3 个 Route B 案例，后续任务族由接口复用性决定”的一层表述。

## 4. 不可宣称项（本轮必须继续保留）

1. Route B 的首轮实施顺序已被接受，**不等于**第三章完整方法、标准评测基准或系统效果已经冻结／验证。
2. “只读离线”只限制评测读冻结制品与记录并禁止 GEE／Drive 写入，**不等于**原专业流程迁移为本地算法。
3. `manual 301` 是人工校准／训练数据，**不是**独立验证；quick corridor baseline、完整 RSS、network-only 与 resistance-supported 状态不得合并。
4. “城市级”“真实任务”“多步流程”均不单独构成创新；候选贡献仍取决于跨任务依赖、故障传播与分层评价的可执行设计及近邻工作比较。
5. 第一章正式机制效果、第二章 `scientific gold` 和方法效果、第三章系统效果仍为 open；全部 `[REF-MISSING]` 必须保留到文献证据准入完成。
