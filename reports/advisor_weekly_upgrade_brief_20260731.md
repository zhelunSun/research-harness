# 一周论文框架升级与下一步汇报简报

> 日期：2026-07-31
> 用途：导师汇报底稿；所有“已完成”均按证据状态表述
> 状态：历史规划简报；现行版本见 `../IDEA_VERSION.md`

## 一、建议本周向导师汇报的核心结论

论文工作总题目暂时保持：

> **面向城市森林遥感的智能方法研究**

三项研究内容的工作标题暂定为：

1. **基于多智能体的城市森林遥感工作流构建**
2. **基于科学约束的城市森林遥感知识库构建**
3. **面向用户的城市森林遥感智能体可靠性验证**

本周完成的本质升级，是把原先偏“系统搭建—知识增强—北京制图应用”的并列结构，
重组为一个递进的 Agent 方法故事：

> **工作流形成与运行 → 科学知识约束行动 → 面向真实用户的可靠性评测**

北京 2025 制图不再决定论文边界，而是作为真实任务、专业制品、历史过程和失败案例
的证据来源。这样既保留已有工作，又使论文不再依赖原项目是否继续。

## 二、三项研究各自新增的明确边界

### 研究内容一

已发表工作证明了多智能体完成遥感分析的初步可行性。新增工作冻结为：

- 类型化任务、工具与工作流图；
- 机器可检查的工作流验证；
- 定向修复、正确停止和可追踪运行；
- 与自由规划、结构化规划等条件进行匹配比较。

第一项研究保留轻量测试，但只回答自身机制是否有效；第三项研究负责跨方法、跨任务、
故障与用户层面的独立可靠性评测，因此两章不重复。

### 研究内容二

知识卡片和 claim ledger 被重新定位为“可追溯的知识与证据底座”，不再解释成完整
人工规则库。2026-07-13 的 129 条是历史快照；当前 ledger 为 147 条候选 claim，
其中 143 条为 candidate、4 条 needs-review，且证据原文定位仍全部为 TBD。

新方法对象是：

> 模型根据当前任务，从证据底座提出最小科学约束，经来源、适用性、冲突和风险准入后，
> 进入 Agent runtime，并通过是否改变行动、停止、升级或结论强度来接受检验。

专家的角色从“预先穷举规则”转为定义高风险边界、校准少量参考约束、抽检模型提案和
裁决争议。这使第二项研究同时保留稳妥的静态 contract 基本盘，并为模型自主提出、
经验触发更新和后续 harness 研究留下上探空间。

### 研究内容三

现有北京资产被重新分为：

- 真实任务与可执行环境；
- 弱样本制图专业流程和传统基线；
- 样本、地图与验证报告等结果制品；
- 类别丢失、混淆和失败分支等故障种子；
- 107 条 GEE 运行记录、64 条结果 manifest 和长篇决策日志组成的 episode reservoir。

这些日志目前只是“轨迹候选”，不能直接称为 RL 数据集。第三项研究的独立贡献将落在
目标用户任务构建、任务—环境—轨迹—结果协议、组合评分器、重复试验、故障恢复和
人机协同校准，而不是再做一遍北京制图或仅报告地图精度。

## 三、专家与 human-in-the-loop 的新方案

专家可达性不再是主要风险，主要问题变为如何减少无效专家劳动并避免角色混淆：

1. 生态学家和绿化管理者负责真实问题、决策效用、可理解性和不可接受错误；
2. 遥感与城市森林专家负责科学适用性、流程正确性和 rubric 校准；
3. 独立评测人员检查任务泄漏、评分器有效性和结论边界。

建议先用“两名目标用户＋两名领域专家”的小型校准组，形成 6--10 个任务候选。
确定性检查先评分，模型评分处理开放内容，专家只审校准样本、不确定项、争议项和关键
失败。正式收集可识别的专家意见或交互轨迹前，应先确认学校的人体参与/伦理审查要求
和数据使用边界。

## 四、开题 50% 的证据口径

目前可以稳妥计入完成基础的内容包括：

- 已发表的多智能体遥感论文、案例和轻量 benchmark；
- URSA 工具层升级及第一项研究新增机制的明确设计；
- 第二项研究的知识资产、治理结构、诊断 pilot 和正式匹配实验设计；
- 北京制图方法、样本、结果、运行记录和决策过程资产；
- 已冻结的新故事线、三项研究边界和跨仓执行门禁。

仍不能作为“已完成结果”汇报的内容包括：

- 第一项研究新增 validator/repair/trace 的匹配 pilot；
- 第二项研究从证据到 task-conditioned contract 的正式 B0--B5 结果；
- 第三项研究的正式任务集、评分器校准和跨方法结果；
- 已清洗的 experience dataset、Agent RL 或自主知识进化收益。

因此，当前工作资产规模已经接近或超过开题 50% 所需基础，但新故事线下仍需补三个
最小闭环。向导师汇报时应把“已有资产”和“新机制已验证结果”分开表达。

## 五、建议只向导师请求三项帮助

1. **章节定位确认**：原则上认可第三项研究从单一制图应用升级为面向真实用户的领域
   Agent 可靠性评测，北京制图作为真实环境与案例，而不是章节全部内容。
2. **代表性场景把关**：请导师帮助确认第二项研究一个高价值科学决策任务，以及第三项
   研究首批 2--3 个用户任务族是否代表城市森林遥感的真实需求。
3. **开题口径与合规路径**：确认“完成 50%”的认定方式、9--10 月开题的选择窗口，
   以及后续专家/用户研究是否需要学院伦理或数据审批。

不建议本轮要求导师决定具体模型、全部对比方法、专家人数或 RL 路线。这些可以在最小
试跑后，用结果支持下一次决策。

## 六、必须主动说明的限制

- “科学约束”和“可靠性验证”仍是工作术语，最终是否改为“证据约束”“可靠性评测”
  要由直接竞争文献和构念有效性决定。
- 第二项研究的 147 条 ledger 是候选治理对象，不是 147 条已验证知识或人工规则。
- G1--G4/Wave 结果是诊断证据，正式 B0--B5 与人类校准尚未完成。
- 470 点历史验证不能充当新的独立最终 gold。
- 历史日志需要清洗、分段和归因，尚不能用于宣称经验学习或 RL 成果。
- Agent RL、自进化和开放式持续学习保持为上探项，不作为按时完成论文的门禁。

## 七、未来两周的最低风险推进顺序

1. 第一项研究实现 validator、定向修复和小型 P0--P3 试跑；
2. 第二项研究从 147 条候选中只选一个任务相关的 10--20 条切片，补原文证据并生成
   第一份 human reference / model proposed / governed contract 对照；
3. 第三项研究把两个制图任务和三个已知失败转成可执行 `EvalTask`，先实现确定性
   grader；
4. 在上述材料形成后，再提交给研究者和导师两个短决策包，而不是要求提前通读全部
   资产或广泛访谈专家。
