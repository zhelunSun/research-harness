# 面向城市森林遥感的智能方法研究：总体 Idea

> Idea version: v2026.07.30
> 状态：工作总题目、三项研究标题和总体主线已接受；节级提纲和实验规模待大纲冻结冲刺后转换

## 标题与叙事约定

工作总题目保持为：

> **面向城市森林遥感的智能方法研究**

三个研究标题采用“核心方法＋研究对象＋研究任务”的中文学位论文结构，不把
runtime、trace、validator、repair、contract、benchmark、RL 等模块全部堆入标题。
这些概念进入方法和节级结构，而不是继续拉长章标题。

## 一、问题出发点

城市森林遥感分析不是一次模型推理或单一步骤数据处理。用户通常从研究目标出发提出开放需求，而完成任务需要同时处理：

- 研究目标向可执行遥感任务的转换；
- 多源数据、专业方法和异构工具的组合；
- 领域知识、方法适用条件、证据边界与验证义务；
- 连续交互中的错误、修复、成本和环境状态变化；
- 当前年份样本不足以及最终结果的不确定性。

现有智能体即使能够调用工具，也不必然形成科学合理、可执行、可追踪且对用户真正有用的研究流程。论文因此不再采用“系统—知识库—制图产品”的项目式叙事，而研究一个完整的智能体科学过程：

> **如何形成工作流，如何约束工作流，以及如何知道它在真实任务中是否可靠。**

## 二、总体科学问题

> 面向知识密集、工具异构且数据与反馈不完备的城市森林遥感任务，如何构建科学知识约束的研究智能体，将开放需求转化为可执行、可追踪的遥感工作流，并从任务结果、运行轨迹和用户效用三个层面提高与评测其可靠性？

## 三、研究内容一：基于多智能体的城市森林遥感工作流构建

### 基本问题

如何把开放、非结构化的用户需求转化为具有明确目标、数据依赖、工具连接、验证义务和失败状态的遥感工作流，并在局部错误发生时完成可控修复？

### 已有基础

已发表 ExpertsRS 工作已经提供：

- Data—Tools—Brain 概念框架；
- 基于多智能体 StateFlow 的需求澄清、任务定义、求解和报告流程；
- 两项案例研究和 20 条请求的轻量 benchmark；
- 与基础模型、单智能体系统的初步比较。

这些证据证明了方法可行性，但不等于已经完成类型化工作流、机器验证、局部修复或轨迹原生 runtime。大论文必须把既有工作标为基础证据，而不是重新计算为新增贡献。

### 新增核心

本项研究冻结为四个互相闭合的机制：

1. **结构化表达**：以 `TaskSpec`、`OperatorSpec` 和 `WorkflowGraph` 表达目标、输入输出、依赖与验证义务；
2. **机器验证**：检查缺失输入、类型不匹配、前置条件、依赖顺序、输出和验证要求；
3. **定向修复**：只修复受影响子图，保留未受影响部分，并在能力不足时停止或请求用户介入；
4. **轨迹化执行**：把状态、计划、工具调用、观察、制品、错误、修复、成本和最终状态写入可审计 `WorkflowTrace`。

### 支撑机制与边界

工具 schema、显式状态、错误规范化、预算、检查点、来源记录和确定性重放是支撑机制。它们对可靠运行必要，但不应分别包装为独立创新。

本项研究不承担：

- 通用分布式 Agent runtime 或完整 Harness 平台；
- 科学知识可靠性与证据冲突处理；
- 长期记忆、Agent RL 或开放式自进化；
- 对“多智能体普遍优于单智能体”的泛化证明。

第一项必须完成自己的局部机制测试；第三项不替代其完整性验证。

## 四、研究内容二：基于科学约束的城市森林遥感知识库构建

### 基本问题

如何把可追溯领域知识、方法适用条件、证据要求和验证边界转化为能够影响智能体规划、执行与结论强度的科学约束？

### 核心 idea

领域知识不应只是被检索和阅读的参考文本，也不应由人类预先写出完整答案。推荐把它表示为作用于关键节点的 `ScientificContract`：

- 方法何时适用或禁止使用；
- 作出某类结论前需要哪些证据；
- 哪些结果必须交叉验证；
- 证据不足、知识冲突或来源不可信时如何降级结论；
- 哪些高风险节点需要人工检查。

人类提供科学不变量、证据准入、风险边界和最终审核；系统提供状态、工具语义、验证器和反馈通道；LLM 负责开放规划、冲突解释和候选决策。这一分工保留 LLM 原生智能，而不是用完整人工规则替代推理。

### 预期贡献位置

- 建立可追溯知识向运行时科学约束的转换关系；
- 研究约束在何种条件下改变规划、工具选择、验证和结论强度；
- 研究冲突、错误或证据不足知识下的拒绝、降级与人工接管；
- 形成可以被第三项研究观测和评分的约束触发轨迹。

### 边界与稳妥性

“科学约束”是当前安全总称；“证据治理”可作为其中证据来源、冲突、充分性和结论校准的子机制，但不宜在尚无完整实验时作为整章唯一总概念。

本项研究不以知识卡片数量、普通 RAG、模型微调、完整人工规则库或知识管理产品作为主要贡献。轻量的模型学习、偏好学习或知识更新实验可作为上探，但不影响基础章节成立。

## 五、研究内容三：面向用户的城市森林遥感智能体可靠性验证

### 基本问题

如何构造能够代表真实城市森林遥感工作的任务、环境、评分器和人机交互，使不同 Agent 方法在最终结果、执行轨迹、失败恢复和用户效用上的可靠性可被复现、比较和诊断？

这里的目标用户优先是提出城市森林专业问题、但不以遥感建模为主要技能的生态学家
和绿化管理部门人员。遥感专家负责建立科学正确性与评分校准，不能替代目标用户的
可用性、理解成本、介入负担和结果信任判断。

### 独立方法对象

第三项研究不是把第一、二项的实验搬到一起，也不是只做北京制图应用。其独立研究对象是：

- **任务协议**：目标、初始环境、允许工具、成功条件、交互条件和预算；
- **试验轨迹**：多次 trial 中的行动、观察、制品、错误、修复和人工介入；
- **可靠性评测**：最终状态、过程正确性、科学约束遵循、鲁棒性、成本和用户效用；
- **故障与恢复**：工具异常、数据缺失、知识冲突、模糊需求和中间产物错误；
- **分层比较**：传统专家流程、通用 Agent、结构化 URSA、科学约束 URSA。

因此，即使不加入自进化或后训练，只要任务设计、评分有效性、故障分析和系统比较成立，本项研究就足以支撑独立章节。

### 北京制图工作的角色

北京 2025 城市森林制图不再决定整章边界，而作为：

- 真实任务、数据状态和专业制品来源；
- 用户—Agent—导师连续反馈的历史轨迹来源；
- 故障类型和恢复策略的经验来源；
- 端到端综合案例和外部效度证据。

弱样本方法本身可作为专业工具或任务难点，不再被迫承担第三项研究的全部创新。

### 可选上探：经验复用与评测引导适应

历史日志先转换为具有任务、环境版本、行动、观察、制品、反馈、结果、评价和来源的 episode。第一阶段用于错误分类、案例检索和经验复用；在评分器稳定后，才考虑：

- 小规模运行配置或工具语义适应；
- 受回归门禁约束的 evaluation-guided harness adaptation；
- 读取同一轨迹的 SFT、偏好学习或 Agent RL proof-of-concept。

这些内容提升职业相关性和研究上限，但不是开题 50% 或毕业基本盘的必要条件。

## 六、三项研究内容的递进关系

```text
开放的城市森林遥感需求
    ↓
研究内容一：形成、验证并修复可执行工作流
    ↓
研究内容二：以知识、证据和验证义务约束科学决策
    ↓
研究内容三：在真实任务中评测结果、轨迹、恢复和用户效用
    ↓
结构化运行经验：支持诊断、复用和可选学习
```

这种关系兼顾：

- **整体性**：三项研究围绕同一个从需求到可靠结果的科学过程；
- **独立性**：每项研究有不同的因变量和证据，不只是同一系统的三个模块；
- **弱耦合**：可以比较冻结版本和外部方法，不要求三个代码仓构成不可拆分的产品；
- **可演进性**：评测与轨迹接口支持未来模型、工具和学习算法更替。

## 七、与 Agent 前沿的吸收边界

统一原则为：

> **轨迹原生、科学约束、评测驱动、经验可学习。**

- AI Second Half 与 eval-driven development 进入第三项研究主线；
- experience-driven agents 进入统一接口和远期承诺；
- Agent RL 作为小规模 sidecar，不作为学位门槛；
- context engineering 是 runtime 中“每一步让模型看到什么”的支撑问题，不单列为创新；
- 有边界的评测引导适应可上探，开放式自进化不进入主线；
- Agent 网络、世界模型只进入展望或个人项目，不与遥感多模态处理硬接。

详细判断维护于 `agent_frontier_alignment.md`。

## 八、开题 50% 的证据解释

“已完成 50%”不能只按代码量或已发表论文篇数计算，而应同时存在：

1. **既有成果映射**：ExpertsRS 论文、工具升级、北京项目、知识卡片和现有原型分别支撑哪条论断；
2. **新旧边界**：明确哪些是已验证结果，哪些是大论文新增方法；
3. **三个问题闭合**：每项研究都有问题、方法对象、拟验证论断和最低证据路径；
4. **新增机制证据**：至少一个超越已发表工作的核心机制已有可运行原型和匹配测试；
5. **第三项研究最小闭环**：已有可执行任务、轨迹格式、一个可校准评分器和至少一次跨方法试跑。

已发表论文和现有工作量使开题基础接近充分，但只有完成上述证据映射与最小闭环，才能避免把尚未完成的第三项研究按叙事预支为 50%。

## 九、大纲冻结前仍需决策

1. 第二项研究的最小可行科学约束表示及首个验证任务；
2. 第三项研究的核心任务族、目标用户招募和专家校准责任；
3. 历史日志的可重放比例，以及后续进入论文或公开资产的边界；
4. 何时只冻结毕业基本盘，何时允许 Agent RL 或适应性上探进入正式计划；
5. 开题定稿时是否有充分理由把总题目的“智能方法”收窄为“智能体方法”。

这些问题通过证据门禁后，再转换为简洁、符合中文学位论文规范的章节标题与节级提纲。
