# 面向城市森林遥感制图的智能方法研究：总体 Idea

> Idea version: `idea-v2026.08.02`
> 状态：已向导师汇报的工作版本未收到新增修改意见；研究内容二进入优先执行

## 标题与叙事约定

工作总题目保持为：

> **面向城市森林遥感制图的智能方法研究**

三个研究标题采用“核心方法＋研究对象＋研究任务”的中文学位论文结构，不把
runtime、trace、validator、repair、contract、benchmark、RL 等模块全部堆入标题。
这些概念进入方法和节级结构，而不是继续拉长章标题。

## 一、问题出发点

城市森林遥感分析不是一次模型推理或单一步骤数据处理。用户通常从研究目标出发提出开放需求，而完成任务需要同时处理：

- 研究目标向可执行遥感任务的转换；
- 多源数据、专业方法和异构工具的组合；
- 领域知识、方法适用条件、证据边界与验证义务；
- 连续交互中的错误、修复、成本和环境状态变化；
- 当前年份样本不足以及最终结果的不确定性。

现有智能体即使能够调用工具，也不必然形成科学合理、可执行、可追踪且对用户真正有用的研究流程。论文因此不再采用“系统—知识库—制图产品”的项目式叙事，而研究一个完整的智能体科学过程：

> **如何形成工作流，如何约束工作流，以及如何知道它在真实任务中是否可靠。**

## 二、总体科学问题

> 面向知识密集、工具异构且数据条件动态变化的城市森林遥感研究，如何构建以用户开放需求为
> 起点、受科学知识和证据约束的多智能体科学分析系统，实现遥感工作流的形成与运行，并在复杂
> 开放场景中验证其科学性、可靠性与可解释性？

## 三、研究内容一：面向开放需求的多智能体遥感科学分析系统

### 基本问题

开放式自然语言需求如何通过多智能体协作转化为可执行的遥感科学分析工作流，并在真实数据与
工具反馈下实现自动执行、动态调整和可解释结果交付？

### 已有基础

已发表 ExpertsRS 工作已经提供：

- Data—Tools—Brain 概念框架；
- 基于多智能体 StateFlow 的需求澄清、任务定义、求解和报告流程；
- 两项案例研究和 20 条请求的轻量 benchmark；
- 与基础模型、单智能体系统的初步比较。

这些证据证明了方法可行性，但不等于已经完成类型化工作流、机器验证、局部修复或轨迹原生 runtime。大论文必须把既有工作标为基础证据，而不是重新计算为新增贡献。

### 章节核心

构建面向用户的多智能体遥感科学分析系统，贯通开放需求理解、角色协作、工作流生成、遥感工具
调用、自动执行和可解释结果交付。动态规划与错误调节不能代替这一系统主线。

### 新增机制

在上述系统和已发表基础上，本项研究新增三个互相闭合的机制：

1. **动态规划**：以分层计划表示未来意图，并根据真实数据和工具反馈调整后续行动；
2. **过程记录与检查**：以随执行更新的过程图记录实际动作、观察、制品、错误和交付状态；
3. **错误调节与局部恢复**：在局部错误发生时保留可复用结果，从检查点恢复，或在能力不足时
   受控停止并请求用户介入。

任务、工具、输入输出、依赖与验证要求的结构化表示是上述机制的共同基础，不单独代替完整系统
或增量机制的科学问题。

### 支撑机制与边界

工具 schema、显式状态、错误规范化、预算、检查点、来源记录和确定性重放是支撑机制。它们对可靠运行必要，但不应分别包装为独立创新。

本项研究不承担：

- 通用分布式 Agent runtime 或完整 Harness 平台；
- 科学知识可靠性与证据冲突处理；
- 长期记忆、Agent RL 或开放式自进化；
- 对“多智能体普遍优于单智能体”的泛化证明。

第一项必须完成自己的局部机制测试；第三项不替代其完整性验证。

## 四、研究内容二：面向智能体的遥感科学知识表示与推理

### 基本问题

如何将分散的遥感科学知识组织为具有来源、适用条件和证据状态的可计算表示，并支持智能体围绕
具体任务开展数据选择、方法执行、验证和结论形成等知识推理？

### 核心 idea

领域知识不应只是被检索和阅读的参考文本，也不应由人类预先写出完整答案。本项研究对知识来源、
适用条件、证据角色、冲突与未知状态、验证义务和结论有效性边界进行任务条件化表示，并通过可
查询、可检查的知识—证据运行界面支持智能体围绕原始科学问题组织观测、分析、验证与解释。

当前章级主术语为**面向智能体的遥感科学知识表示与推理**。任务条件化表示、来源、适用条件和
证据状态是方法属性；`ScientificContract` 只是一种
候选紧凑投影；“科学认知环境”只用于解释智能体可见的知识、证据、工具和反馈条件，二者均不
代替章节方法。模型保留开放规划和候选决策；人类负责科学边界、评审校准和高风险争议裁决。

### 预期贡献位置

- 建立面向遥感研究任务的科学知识和证据状态表示方法；
- 建立知识—证据运行界面，支持智能体开展面向任务的知识推理而不规定唯一流程；
- 在等知识内容与正负证据条件下，区分流程执行、产品结果、科学意图、严重错误和不必要干预；
- 形成可供第三项研究观测和评分的推理、行动与结论记录。

### 边界与稳妥性

“遥感科学知识表示与推理”是当前章级主术语；“科学约束”可作通俗上位词或表示内容，
“科学认知环境”只作设计隐喻。具体形式、效果和跨任务泛化仍待验证。

本项研究不以知识卡片数量、普通 RAG、模型微调、完整人工规则库或知识管理产品作为主要贡献。轻量的模型学习、偏好学习或知识更新实验可作为上探，但不影响基础章节成立。

## 五、研究内容三：面向城市森林遥感任务的智能体系统评测

“系统验证”是标题层面的上位表述。其内部方法是面向真实复合任务的系统与过程评测，
不以端到端展示、一次北京制图案例或单一地图精度代替任务、过程、故障和结果层面的验证。

### 基本问题

如何基于具有多阶段依赖、环境变化和可观察过程的真实城市森林遥感任务，建立能够检验任务组织、
输出结果、科学一致性和能力边界的智能体系统评测方法？

这里的“面向用户”首先表示任务由城市森林研究或管理目标驱动，系统需要接受开放需求并交付可
解释结果。目标用户和遥感专家可参与任务与评价校准，但正式用户效用研究不是当前核心方法或
最低承诺。

### 独立方法对象

第三项研究不是把第一、二项的实验搬到一起，也不是只做北京制图应用。其独立研究对象是：

- **复杂场景表示**：大型城市、多源数据、跨环节指标和跨学科知识依赖；
- **复合任务组织**：从遥感制图、植物生态、景观格局、生态系统服务和管理解释的关系中，先组织
  两至三条可检查的跨环节任务链；
- **试验协议**：目标、版本化环境、允许工具、成功条件、关键失败和预算；
- **系统评价**：任务组织、跨步骤一致性、科学一致性、环境适应、故障处理、结果追溯和成本；
- **故障与恢复**：工具异常、数据缺失、知识冲突、模糊需求和中间产物错误；
- **分层比较**：冻结专业流程、通用工具型 Agent 和本文完整系统；第二章界面只在必要时作为条件变量。

因此，即使不加入正式用户研究、自进化或后训练，只要复杂场景表示、复合任务组织、评价有效性、
故障分析和系统比较成立，本项研究就足以支撑独立章节。

### 北京制图工作的角色

北京 2025 城市森林制图不再决定整章边界，而作为：

- 真实任务、数据状态和专业制品来源；
- 用户—Agent—导师连续反馈的历史轨迹来源；
- 故障类型和恢复策略的经验来源；
- 端到端综合案例和外部效度证据。

弱样本方法本身可作为专业工具或任务难点，不再被迫承担第三项研究的全部创新。

### 可选上探：经验复用与评测引导适应

历史日志先转换为具有任务、环境版本、行动、观察、制品、反馈、结果、评价和来源的 episode。第一阶段用于错误分类、案例检索和经验复用；在评分器稳定后，才考虑：

- 小规模运行配置或工具语义适应；
- 受回归门禁约束的 evaluation-guided harness adaptation；
- 读取同一轨迹的 SFT、偏好学习或 Agent RL proof-of-concept。

这些内容提升职业相关性和研究上限，但不是开题 50% 或毕业基本盘的必要条件。

## 六、三项研究内容的递进关系

```text
开放的城市森林遥感需求
    ↓
研究内容一：形成、验证并修复可执行工作流
    ↓
研究内容二：以任务条件化科学知识表示支持知识推理
    ↓
研究内容三：在真实城市森林遥感任务中评测完整系统
    ↓
结构化运行经验：支持诊断、复用和可选学习
```

这种关系兼顾：

- **整体性**：三项研究围绕同一个从需求到可靠结果的科学过程；
- **独立性**：每项研究有不同的因变量和证据，不只是同一系统的三个模块；
- **弱耦合**：可以比较冻结版本和外部方法，不要求三个代码仓构成不可拆分的产品；
- **可演进性**：评测与轨迹接口支持未来模型、工具和学习算法更替。

## 七、与 Agent 前沿的吸收边界

统一原则为：

> **轨迹原生、科学约束、评测驱动、经验可学习。**

- AI Second Half 与 eval-driven development 进入第三项研究主线；
- experience-driven agents 进入统一接口和远期承诺；
- Agent RL 作为小规模 sidecar，不作为学位门槛；
- context engineering 是 runtime 中“每一步让模型看到什么”的支撑问题，不单列为创新；
- 有边界的评测引导适应可上探，开放式自进化不进入主线；
- Agent 网络、世界模型只进入展望或个人项目，不与遥感多模态处理硬接。

详细判断维护于 `agent_frontier_alignment.md`。

## 八、开题 50% 的证据解释

“已完成 50%”不能只按代码量或已发表论文篇数计算，而应同时存在：

1. **既有成果映射**：ExpertsRS 论文、工具升级、北京项目、知识卡片和现有原型分别支撑哪条论断；
2. **新旧边界**：明确哪些是已验证结果，哪些是大论文新增方法；
3. **三个问题闭合**：每项研究都有问题、方法对象、拟验证论断和最低证据路径；
4. **新增机制证据**：至少一个超越已发表工作的核心机制已有可运行原型和匹配测试；
5. **第三项研究最小闭环**：已有可执行任务、轨迹格式、一个可校准评分器和至少一次跨方法试跑。

已发表论文和现有工作量使开题基础接近充分，但只有完成上述证据映射与最小闭环，才能避免把尚未完成的第三项研究按叙事预支为 50%。

## 九、大纲冻结前仍需决策

1. 第二项研究的最小可行科学约束表示及首个验证任务；
2. 第三项研究的复杂场景边界、首组复合任务依赖和评价有效性；
3. 历史日志的可重放比例，以及后续进入论文或公开资产的边界；
4. 何时只冻结毕业基本盘，何时允许 Agent RL 或适应性上探进入正式计划；
5. 开题定稿时是否有充分理由把总题目的“智能方法”收窄为“智能体方法”。

这些问题通过证据门禁后，再转换为简洁、符合中文学位论文规范的章节标题与节级提纲。
