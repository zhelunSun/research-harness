# 文献组织小实验：固定底层、可变视图

## 预先限定的协议

这是文献管理工具的局部诊断，不是论文实验或通用检索 benchmark。
不导入、不改 Zotero 标签/collections、不读取 PDF/私人笔记、不扩大文献搜索。
案例在第一次运行前写入 `cases.json`；保留上一轮已试过的四题，并单独报告四个
新改写和四个已知题名/标识/标签案例。新措辞也由同一 agent 构造，不是独立盲测。
本轮运行后不为提高分数调整关键词、权重或预期条目。

对同一份本地 catalog 比较三个入口：

1. **metadata**：标题、已有标签、collection 路径、作者、标识等现有元数据；
   去掉证据文本和问题包提示，但保留相同的分词/中英文展开。另报 `metadata_keywords`：
   使用第一次运行前写入的英文关键词，模拟将模糊中文需求转换成传统检索词；不以
   原样中文在英文元数据上的失败，证明标签/collection 不好。
2. **question**：上一轮已经实现的问题增强检索；它也使用元数据，不是排他的“问题文件夹”。
3. **hybrid**：`metadata_keywords` 与 `question` 两路前 30 名的等权
   reciprocal-rank fusion，常数固定为 60。

另做两个边界检查：

- 对真实 Zotero `AI4Science` 标签和 `AI_basis/AI_for_Science` collection 做精确筛选；
  这是对已有组织的利用检查，不将缺少登记的证据包论文计作传统分类失败。
- 在内存里归档一个问题视图，验证底层文献与标签/collection 不变；同时观察把 R2
  强行限制在旧 `scientific-discovery` 范围时的候选损失。后者是显式限制的模拟，
  不是对 Zotero collection 模型的描述，也不把“归档视图不删文献”的设计保证包装成实证优势。

## 评价边界

`known-anchor coverage@5` = 前五名找回的预先列出来源数 / 该题列出来源数。
这些 anchors 来自既有证据卡；未命中不是库里不存在，非 anchor 命中也不一定不相关。
因此不报告全库 recall、precision、统计显著性或人类浏览效率。只记录轻量本地查询时间，
不把它当作人类找到可引用证据所需的时间。新实验不升级任何阅读或论断状态。

候选池包含未入 Zotero 的证据包条目；所有策略使用同一候选池，但元数据丰富度不齐。
单独报告 Zotero 内/外 anchor 数，以及整个个人库的标签/collection 覆盖。
扫描 fingerprint 和本地结果保存于忽略目录；不把全库缓存推送到 Git。

## 复现

```powershell
python -X utf8 scripts/literature_catalog.py scan --write
python -X utf8 scripts/pilot_literature_organization.py --write
```

完整逐题结果位于 `.cache/literature/organization-pilot.json`。摘要与评估在首次运行后
追加到本文；源案例和排名策略保持不变。

### 具体观察

- `AI4Science` 的真实标签筛选返回 5 条，5 篇全部找回；原有
  `AI_basis/AI_for_Science` collection 返回 14 条，也包含这 5 篇。传统导航无需被替代。
- R3“**不做树种分类了**，想讨论绿地带来的收益”：问题入口仍把树种分类论文排第一，
  虽然前五名包含两篇预期生态服务材料；英文关键词把这两篇排在前两名。
  **已命中词不等于理解了否定或新意图。**
- R2 从写报告转到数据分析验收：英文关键词找回 2/3 个预期来源，问题与简单融合均为
  0/3。融合不是保底：共享但偏题的结果可能挤掉单路较好的候选。
- R1 的“教训迁移”没有直接说“经验”；问题入口漏掉 ExpeL，融合找回它，但并未同时
  找回全部预期来源。语言改写和概念别名是短板，不是文献一定缺失。
- R4 反问错误知识和争议，问题入口偏向执行规则的论文，没有找回预定的挑战关系和
  适用性材料。它不能用于自动判断论文立场或支持/反对关系。
- 强行将 R2 留在旧 `scientific-discovery` 范围，候选只剩 9 条，三个预期评价来源
  全部落在范围外。这是限制范围的模拟，问题视图和 collection 都可能发生；不是
  Zotero collections 本身会损坏文献。内存归档实验保留全部 598 个底层 entry，
  标签/collection 元数据完全不变，说明可把问题层设计为可撤回指针。

### 另行修复的确定性缺陷

K1 的 Co-Scientist DOI 在四个冻结检索策略中均漏出前五名：普通分词把 `10` 当成了
高权重标题词，反而优先返回“10 m 制图”类论文。保留上述 75% 原始结果，没有改词重算。
正式 `literature_catalog.py query` 入口现增加 DOI、既有 item/BibTeX key、精确标题优先
路由；未知 DOI 返回空结果，不退回数字词匹配；多个相同 DOI 的记录保留供核对，不合并。
修复后单独复核同一 DOI，精确返回 `ETGXFWI5`。底层 `search()` 及本实验策略没有修改，
故该修复不计为自然语言检索提升。

## 评估与建议：并存，不统一强制分类

1. **稳定底层**：保留现有书目身份、版本、附件和历史。研究问题被推翻不影响文献存在。
2. **传统导航**：保留已有 collection；标签允许主题、方法、对象、阅读状态等多种维度，
   不要求每篇填满模板，也不强制改成统一命名体系。自动导入标签不当作人工审核标签。
3. **临时工作视图**：研究问题、某章用途、支持/限制某论点，都作为带日期/状态的链接。
   可同时服务多个问题；问题改变时归档/重算链接，不搬文件、不删除记录、不重写旧证据。
4. **多个检索入口并列**：已知文献先精确查找；主题浏览用标签/collection；模糊问题走
   关键词转换与证据候选。现阶段保留两路候选更可检查，不自动采用一个融合总排名。
5. **下轮候选而非本轮接受的能力**：用日常实际提问检查别名、否定和目标转换；先在已有库
   上积累少量未调过的案例，再决定是否需要全文/语义索引。无需等待最终提纲，也不扩大外搜。

Zotero 官方说明同一条目可属于多个 collections，且这种关系不会复制文献：
[Collections and Tags](https://www.zotero.org/support/collections_and_tags)。
本次没有 Zotero 写入或证据状态晋级；检索结果、实验指标和库内数量也不构成论文科学证据。
