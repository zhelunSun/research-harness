# DEC-2026-0831：开题简洁共识、工作标题与验证边界

## 状态

2026-08-31：Accepted for the opening-material source definition。

本决策在 `DEC-2026-0830` 和 `DEC-2026-0831-opening-objectives-content-and-route-alignment`
的基础上进一步压缩三项研究的共同对象、工作标题和验证边界。它更新开题材料的工作标题与
源定义，但不冻结最终送审题目，不改变已有证据等级，也不自动发布新的 Idea 版本。

## 三项研究的工作标题

1. **面向开放需求的多智能体遥感科学分析系统**；
2. **面向智能体的遥感科学知识表示与推理**；
3. **面向城市森林遥感任务的智能体系统评测**。

第一项以完整系统为章节核心，遥感工作流是贯通需求、协作、工具执行和结果交付的核心载体；
动态规划、过程记录、错误调节和局部恢复仍是增量机制。标题使用“多智能体遥感科学分析系统”，
避免“多智能体科学智能体系统”的概念重复，也不把章节收窄为单一工作流算法。

第二项保持遥感领域尺度，以便与拟开展的小论文和跨任务验证目标一致；城市森林是主要深度案例
和任务来源，而不是知识方法唯一适用范围。章节主术语恢复为“遥感科学知识表示与推理”。来源、
适用条件、证据状态、验证义务和结论边界是知识表示与推理需要处理的科学属性；“证据约束推理”
不再作为章名或需要单独建立共识的新术语。

第三项以“城市森林遥感任务”限定评价范围，不使用难以直接操作化的“复杂任务”作为标题标签。
任务区别由正文和试验协议具体说明：包含多阶段依赖、数据或工具环境变化、中间制品传递、过程
可观察以及结果和结论可追溯。北京是首个资产与试验来源，不限制评测方法只能用于单一城市。

## 共同对象链与用户定义

三项研究共享以下简洁对象链：

> **城市森林遥感任务 → 多智能体科学分析工作流 → 知识支持的产品与结论 → 智能体系统评测**

“城市森林遥感任务”已经包含领域问题、预期用途、时空范围、所需产品、约束和待澄清事项，
不再另立一个“领域问题到遥感任务”的独立研究环节。

本研究所称领域用户，主要指贴近城市森林科学问题与规划管理场景、但不以遥感数据处理为主要
专长的研究与实践人员。第一项可设置由 Manager agent 承担的“开放需求解析与任务澄清”功能，
但在缺少专门数据和评价前，不把通用用户意图识别包装为独立算法贡献或正式用户研究。

## 三章局部验证与第三章系统评测的边界

- 第一项的局部实验检验工作流贯通，以及动态规划、过程记录、错误调节和局部恢复的增量作用；
- 第二项的局部实验检验知识表示与推理在等知识内容、不同证据状态下的作用及不必要干预；
- 第三项不重复上述全部消融，而在多阶段任务中比较专业流程、通用智能体和本文完整系统，并以
  “第一项系统—加入第二项机制的完整系统”作为有限的系统级模块拆分或消融条件；
- 第三项关注局部增益能否在组合后保留、错误如何跨环节传播以及系统在何种条件下失效，不重新
  声称证明第一、二项的单项机制。

这些判断属于研究设计经验，应由 decision 与源定义保存，不进入简版提纲的主要篇幅，也不只留
在聊天记录中。

## 第三项研究的下一门禁

第三项研究需要在 `urbfo-agent-demo` 所属仓库内开展一次“资产—评测—结论”核对，逐项确认：

1. 现有数据、代码、制品、运行记录和历史故障能构造哪些多阶段任务；
2. 哪些依赖、结果、来源和故障能够确定性检查，哪些需要领域校准；
3. 专业流程、通用智能体和本文系统是否能够在同一环境中公平运行；
4. 当前资产能够支持哪些系统评测结论，哪些仍需新建数据、任务或文献依据。

该核对属于第三章仓库的执行与证据工作；总控仓只维护入口、结论边界和接收状态。
