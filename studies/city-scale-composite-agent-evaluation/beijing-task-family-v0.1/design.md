## 1. 研究问题与操作对象分开

总体问题候选聚焦北京既定研究区的空间格局、潜在连通性、空间差异与待核查薄弱环节；不是论证城市森林健康、真实物种通行或管理措施有效。底图或尺度敏感性是条件性扩展，不列为首轮必需回答。

观察年份先以现有 2025 年制图工作为候选，边界先引用 BJuforebv4，但不等于已通过本任务的适用性审查。空间比较单元、目标类别与支持的生态解释仍需确定。[CRITICAL-CHECK:scope-and-object-definition]

Level 1 QA 原文把 tree、shrub、grass、wetland 合为前景，并排除 cropland。这是已记录的制图操作口径，不是本轮新批准的生态定义。保留它用于历史复现；若领域问题需要改变前景，必须另建版本和比较条件，不覆盖原结果。

## 2. 三项子问题怎样产生同一个回答

| 任务 | 建设性的知识作用 | 需要的证据与产物 | 科学验收候选，不是已批准阈值 |
| --- | --- | --- | --- |
| T1 底图与空间格局 | 把研究对象与观测类别联系起来，选择合适年份、类别映射和验证证据 | 数据与类别说明、底图、可追溯的空间差异摘要 | 数据是否支持提出的对象／时段；描述是否由对应产品支持；没有独立验证时是否保持适当结论范围 |
| T2 核心栖息地形态 | 选择能够回答形态差异的方法，解释尺度与边界效应 | 同一底图上的核心栖息地图层、方法参数、对象统计及比较 | 对象及统计是否可复核，比较是否有明确参照，形态定义是否被误当作物种栖息证据 |
| T3 潜在连通性 | 组织空间网络分析，区分邻接、网络与阻力证据，合理使用基质背景 | 同一组核心栖息地、连边／廊道、基质或阻力来源、证据分级 | 节点与上游对象是否一致；连接解释是否对应实际证据；无阻力结果时不能声称生态通行成立 |
| S 综合回答 | 连接结果与总问题，保留适用范围与不确定性，而不是拼接四份报告 | 可定位的结论—产品—来源对应表 | 必要子问题是否完成，结果是否兼容，综合判断能否逐项回到原始数据与计算 |

不足或冲突状态用于检验适当收窄，充分证据状态用于检验能否完成更多正确分析。拒绝执行所有分析不能获得总体成功；机械输出全部指标也不算回答了问题。

依赖图是科学产品之间的关系，不规定智能体唯一工具顺序。允许不同有效算法、检索次序和等价解；不能仅因输出没有采用我们的知识字段而扣分。

## 3. 实物核查与可恢复性

specification.json 保存本轮指定路径的存在性和文件哈希，来源均在 canonical Chapter 3，revision 为 6f1482cf07ca7ef5f3d21cd3bd3d888bb5a4cdc2。未扫描或写入 recovery 区，未验证外部云端数据。

| 实物组 | 核查结果 | 能支持／不能支持 |
| --- | --- | --- |
| 指标矩阵与 profiles | 原文／派生文件存在 | 可用于组织任务；不能视为已校准的完整指标体系 |
| 指标注册表 | canopy_cover、edge_core_ratio 为 draft；canopy_height 为 planned | 不能声称三个指标均已可用 |
| 当前 Route B 评测 fixture | 版本化协议和三个只读案例存在 | 支持协议检查；科学有效性仍为 not-assessed |
| 形态／网络配置 | 存在 Route B Level 1 到 RSS 的 source alias | 支持声明的衔接路径；不是实际跑通或参数已适用的证据 |
| AOI 四个组件 | 存在且记录哈希 | 仅核查文件存在性；未重新验证几何、研究范围或生态适用性 |
| 本轮六个重型制品路径 | Level 1 栅格、选定核心栖息地／网络以及旧 full/smoke 网络节点均未找到 | 仅限指定 canonical 路径；不推断其他磁盘或云端已丢失 |

具体风险：

- configs/workflow_state.yaml 是 2026-06-13 的 scaffold，不替代当前 PLAN。
- canopy_cover 卡片实际写的是 broad vegetation cover proxy；zonal 配置中的 canopy_proxy 采用类别权重，不是已验证树冠覆盖测量。
- zonal 配置中 bsi_mean 指向裸地比例字段；在科学命名与公式核验前，不把它当作光谱裸土指数。
- 完整 RSS、quick corridor baseline、network_only 与 resistance_supported 必须分开；旧 full/smoke 状态不自动证明 Route B source alias 的当前执行状态。
- manual 301 始终为校准／训练数据；固定 470 点的历史诊断不能变成未触碰确认集。

范围确认后的准备顺序：定位指定底图与图层的已有备份／资产 ID → 核查 revision、许可、哈希与时空元数据 → 仅恢复获准的最小输入 → 复核参考计算与替代正确解 → 由研究者接受科学验收。[CRITICAL-CHECK:scientific-acceptance]

如果无法获得重型制品，只能先完成记录审计；这不是完成了 T1--T3。不得用合成栅格或重新导出的另一版本偷偷填补既有结果。

## 4. 第二章的最小对照怎样接入

当前 Ch2 两任务先行决定在其所属任务中维护。本包不改变该顺序，不指定开发／确认任务，也不把同一北京数据的两个派生子问题当成两个独立确认任务族。

| 层次 | 应控制什么 | 可以回答什么 |
| --- | --- | --- |
| 完整方法 | 同一可访问资料库、模型、工具、预算与交付要求；记录检索及人工准备成本 | 整套知识支持是否改善已测任务 |
| 表示／可检查性 | 专业事实、关系、来源与边界语义相当；不在文本组故意删减关键关系 | 组织或访问方式的增量 |
| 交互支持 | 在相同原始事实下加入可追溯的检查反馈 | 运行支持组合的增量，不自动归因于单一组件 |

强基线应能迭代检索与调用工具，不能仅与不给知识的模型比较。普通检索取得不同资料，属于完整方法效应的一部分；它不能用来单独证明结构化表示更好。

反馈不得携带隐藏参考答案、正确动作或故障标签。评分侧保存的参考结果和容差不得进入智能体可读目录。specification.json 是设计审阅材料，本身也不能整份提供给被测智能体。

## 5. 第三章评价的三个层次

1. 单任务：规定的分析结果是否正确形成、证据是否充分；执行完成与科学成功分开。
2. 跨任务：产品身份、对象、单位、时段、空间转换与结论是否兼容；一致但共同错误不算正确。
3. 总问题：必要子问题与综合解释是否完成；不能用子任务平均分掩盖关键依赖失败。

孤立测试使用参考中间输入；完整链测试使用被测系统前序输出。两者共同帮助区分本步能力与前序失败，不把重复运行或派生任务计作独立城市样本。成本、人工介入、无根据拒答、缺失评分和运行失败另行报告。

若研究敏感性，只比较科学上可比且明确获准的产品或设置；没有这样的配对时保留未评估，不开展大规模参数扫描。正确替代路径、外观完整但结果错误、证据不足却强结论、不必要拒答均应在评分器校准中出现，具体参考值与严重错误判定仍待人工接受。
